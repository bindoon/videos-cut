# 预览、批注与改片

工具参数与文件合同见 [review 工具](../../docs/review.md)。继续使用当前影片的渲染路线，原始素材和此前结果均保留。网页只播放实际视频和写入本地批注，不内置 AI，也不执行渲染命令。

## 登记、生成、发布

在第一次审片前，给可编辑配置中的镜头补上显式 `id`；不要用改动后的标题重新生成 ID。素材混剪的实际 `timeline.json` 会保留场景字段；codefilm 使用自己的场景 ID 和原工程时间。

1. 用 `review prepare` 登记本次配置、声明输入和一个尚不存在的候选视频路径。素材路线使用已解析为本地 `path` 的素材表；代码路线读取 codefilm 声明输入。额外影响像素的素材、字体、配音等用 `--source` 声明。
2. 使用已有渲染工具输出候选和实际时间轴。局部预览登记原工程偏移与时长；不能把局部预览作为整片。
3. 完成渲染并核对对应报告后执行 `review publish`。发布会再次核对输入摘要、完整解码/帧数和镜头范围，封存实际视频。失败时读取错误，保留旧版；源文件变更则显式 `abandon`，重新登记、渲染，不改摘要放行。
4. `review serve` 启动本地审片页。界面显示的版本应以视频加载完成为准；旧画面仍在播放时，不能声称新版已完成。

## 处理批注

用 `review comments --claim` 领取一条待处理批注。读取版本、预览时间、原工程时间、镜头 ID、可选画面区域、原配置快照及当前源文件变化，再看对应画面。旧版意见不会自动重定位到最新镜头。

按具体要求修改配置或场景源码。若当前工程已有其他改动，先核对用户意见是否仍适用，不能用旧快照覆盖新文件。修改后登记新候选、实际生成、发布并检查；`review resolve --result-revision ... --note ...` 引用确有变化的新版，回复具体改了什么。参数修改可由 Agent 直接改原配置，首版网页不提供通用源码编辑器。

图片的裁切/时长/运镜和 Three.js 的相机变化需要按各自 renderer 实现；画面区域只是定位线索，不表示工具识别出三维对象或能拆出 MP4 中的独立图层。

## 交付判断

review 的 `integrity.passed` 只说明审片文件与封存记录一致且可解码。ASR、Qwen/sync.py、动作几何验证和艺术判断分别报告；未运行保持未验证。导演节奏和静止指标按 [video-direction](../video-direction/SKILL.md) 判断，不为了消除提示改掉用户认可的慢镜或阅读停留。
