# 小红书字幕图文

本技能负责内容与版式决策；执行由仓库的 `videocut download / transcribe / images` 完成。通用工具不包含小红书选题、平台文案或自动发布规则。先定位仓库根目录（本文件上三级），阅读 `docs/image-tools.md` 的输入合同；端到端示例与边界见 `docs/workflows/xiaohongshu-quotes.md`。

## 从输入到可用选题

- 用户给 URL 时使用已有 `download`，读取真实 `materials.json`、字幕轨及来源记录。先看候选帧；字幕轨、ASR 文字都不证明画面里有烧录字幕。下载失败沿用项目的错误与重试机制，不另外读取浏览器 Cookie，不重复搭建下载器。
- 没有文字时间轴且需要理解长视频时，用独立 `transcribe`；复用原有缓存，不改写其词时间。已有 SRT/VTT 或 ASR JSON 通过 `images index` 变成检索索引。`no_speech` 可以没有索引句子，不能据此编造台词。
- 宿主 Agent 阅读文字稿，按用户受众提名 2–3 个主题，或直接采用用户指定片段。每个主题记录标题、核心意思、原句与上下文、时间范围、候选时间点及说话人依据。标题和概括不自动成为人物引语。优先连续表达；拼接相距很远的句子时明确说明，不制造原视频中不存在的问答或因果。
- 多人对谈的说话人需要看画面或听录音核实；不从文字轨推断声音归属。工具没有自动说话人识别。

## 确定字幕来源与画面

尊重用户已指定的原生/脚本模式，不重复询问。意图不明确时，先取帧说明素材条件，再询问需要保留原字幕还是绘制校对后的台词。不能静默切换。

- **原生模式**：每行只填 `time`，用 `images band` 检查字幕上下边界，直接保留原画面像素。不得用 OCR、ASR 或翻译重绘后声称原生字幕。
- **脚本模式**：填写 `text`、`text_source.kind/reference` 和 `reviewed=true`。先依据视频或用户稿件校对；翻译记为 `translation`，压缩改写记为 `edited`，都属于后期文字。`reviewed` 是调用方声明，不能声称工具核实了人物原话。
- 对每句使用 `images sample --at 秒数 --around 0.4` 查看前、中、后候选；避开字幕切换、黑帧、闭眼与镜头切换。首图尽量包含实际说话人的完整脸部。必要时缩小或扩大采样范围，但不跳到另一句。

## 排版与出图

把本目录 `assets/` 的 manifest 复制到任务目录再改，素材路径相对 manifest。原生参考 `native.json`，脚本参考 `script.json`。

- 通常每图 4–6 句，工具每图允许 2–7 个严格递增时间点；更多句子拆图，不压扁画面或字幕。
- 小红书图文可选 3:4 固定画布。原生模式完整拼接后统一缩放、留边，保持各句字幕相同缩放倍数；留边太大可选自然布局，不能为填满而单独放大字幕或人物。
- 脚本图默认先用主图约 60%、其余字幕条均分，逐张调整；文字过长应拆条或改排版。`fit=cover` 会裁画面，查看人物是否被裁；`contain` 保留画面比例并留边。
- 先 `images plan`，再 `images render` 到新目录；已有任务用 `--resume`。它按视频、时间点、文字、样式、字体及渲染器摘要重算变化项，并保留旧版本图片。失败时读报告，修正后续跑；不能把旧总览当成本轮成功。
- 重复字幕条默认阻止原生出图。只有确认重复确有内容用途，才在该卡写明 `duplicate_reason`；不要为通过检查批量绕过。

## 交付

执行 `images verify`，再实际打开每张 JPG 和总览图，检查文字完整、字幕条无重复、人物与台词对应、比例和构图合理。机械校验通过不等于语义或视觉审核通过。

交付图片、当前 `image-report.json`、manifest、来源与逐图检查结论。用户需要图文文案时，另写 `publication.json`，包含标题候选、正文、标签和来源署名；不把这些文案塞进人物字幕。只要求截图时无需扩展为运营策划。发布行为需用户另行指令，技能不自动发布，也不承诺传播量或固定制作耗时。
